# vivo V2458A / Android 16：自主容器实验版

此版本为 `0.2.2-container-alpha`，尚未实现游戏内汉化，也没有确认《边狱巴士》能在容器中运行。此轮验证容器真实执行路径与首个游戏兼容问题，不要求 Root、Shizuku 或无线调试。

## 安装

从成功的 Actions 运行下载 `LCBLauncher-container-alpha-apk`，解压安装 APK。云端使用临时调试签名；如果提示与旧启动器签名冲突，需要先导出旧诊断、卸载旧启动器再安装。不要卸载原版游戏。未来容器存有资源后，不能通过卸载来常规更新。

## 1. 容器自检

1. 打开首页「自主容器」，点击「运行容器自检」。
2. 应进入独立容器页面，看到 `GUEST_RESOURCE_OK`、`GUEST_ASSET_OK` 和 `GUEST_COUNT=1`。
3. 返回，再运行一次，计数应递增。重新导入自检代码不会删除客体数据。
4. 若失败或闪退，回启动器「工具」导出 JSON，记录最后执行阶段。

自检客体由本项目编写，是未安装到系统的普通 Activity APK；自检通过不代表游戏兼容。

## 2. 导入与实验启动

1. 保留已安装的原版游戏，关闭游戏，点击「导入已安装的原版游戏」。
2. 新版已调整原生库大小上限，并显示提取中的库名和大小。当前已知安装由 base、UnityDataAssetPack 和 ARM64 分包组成。导入会复制安装包并提取原生库，需要额外空间；请保持启动器前台，等进度结束。
3. 点击「实验启动容器内游戏」，阅读实验状态说明后启动。
4. 观察是出现游戏画面、显示容器失败阶段，还是直接返回。容器不会回退打开系统原版。
5. 返回启动器，导出 JSON，附上观察到的情况。若有游戏画面，说明到达标题、登录还是下载页面；仅能打开页面不算登录通过。

原版资源、账号与存档暂不迁移。不要为了此轮测试反复下载大体积资源；若已经到达下载页面，先报告结果。

首页已改为导入 / 测试启动的单一主操作；离线汉化包在「资源」页，诊断导出和原版启动在「工具」页。导入失败会在首页保留详细原因。

## 尚未实现

原生 IO 路径映射、完整组件调度、游戏保护兼容、容器 Google 登录、游戏内中文及字体。当前存储 Context 映射只是基础阶段。系统原版启动按钮仍作为明确标识的诊断入口。

诊断不包含账号、存档、设备唯一标识、游戏 APK 或译文正文。客体进程与启动器具有相同 UID，不能当作不可信应用的安全隔离沙箱。

## 0.2.2 Application 初始化定位

本轮真机已确认 1.118.0 导入成功；旧诊断最后记录 `creating_application`，没有 Java 异常记录，尚不能确定是初始化中还是进程已经退出。0.2.2 分开记录加载 Application 类、构造 / 绑定及 Application.onCreate，并查询系统对启动器自身容器进程的退出记录。不会打开原生崩溃 trace、导出系统描述或采集账号内容。

安装后重新导入原版，测试一次容器启动；若立即返回，稍等 2–3 秒，再在「工具」中导出诊断。若停留黑屏，可先等待约 15 秒，再返回工具页导出。请同时描述看到的是闪退、黑屏还是游戏画面。此版本是初始化定位改进，不宣称游戏运行兼容已经修复。
