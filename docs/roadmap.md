# 自主开发路线与当前边界

## 第一阶段：可测试的诊断基线

- [x] 独立 Kotlin / Compose 工程，不引入现成启动器或容器源码。
- [x] 指定包可见性、游戏版本和 base/split 结构检测。
- [x] ABI、实际内存页大小、内存和存储检测。
- [x] 明确标识的原版启动与手动反馈记录。
- [x] 系统文件选择器导出诊断。
- [x] ZIP 文本资源结构检查、内容哈希与事务式缓存。
- [x] 有界解压、路径验证、UTF-8 与 JSON 检查的核心测试。
- [x] vivo V2458A Android 16 设备识别、原版启动手动反馈与诊断导出验证；所有界面布局尚未完整验收。

第一阶段 APK 是技术探针，尚未实现游戏内汉化。原版启动和包审计都是实际功能，但不能替代汉化接入验证。

## 第二阶段：自主容器（当前主线）

用户已选择直接开发容器。真机上的系统文件管理器可查看游戏本地化目录但不能写入，停止把手动替换、Root 或无线调试作为前置步骤。

- [x] 独立编写 base/split 快照、哈希与 base 证书校验、原生库提取和事务启用。
- [x] 独立客体进程、DEX/资源加载、Java Context 目录映射和 Activity 执行。
- [x] 原创普通客体 APK，以及 Android 16 模拟器上的执行与数据保留测试代码。
- [x] 云端 API 36 x86_64 模拟器执行通过：未安装客体的代码、资源、assets、独立 PID、二次导入数据保留和新进程重开。见 [运行 41034682899](https://github.com/YoisakiKnd/LCBLauncherCN/actions/runs/41034682899)。
- [ ] vivo ARM64 自检和游戏首次实验启动。
- [ ] 实际游戏 Application/Activity 绑定、必要组件调度与 Unity 标题页。
- [ ] 原生 IO 映射、Google 登录、资源下载及后台恢复。
- [ ] 原创中文测试文本与字体在游戏中显示，重启可复现。

设计和当前限制见 [容器运行时](container-runtime.md)。公开 Instrumentation 创建的 Activity 还不是完整虚拟系统；普通测试 APK 通过不能作为游戏兼容证明。验收前不启用「启动汉化版」按钮。

## 第三阶段：汉化资源与显示

- 用结构化上下文配对译文，保持 ID、资源键和语音字段不变。
- 验证实际游戏版本、资源版本、文本格式和中文字体渲染。
- 加入补丁预备、原子启用、失败回滚与恢复原文。
- 缺失或无法可靠匹配的内容保留原文。
- 使用第三方译文前记录其来源与许可，程序原创不改变译文版权。

验收：主页、剧情、战斗技能说明可读，富文本和动态数值正确，失败时可以恢复。

## 第四阶段：更新与维护

分别管理游戏版本、汉化版本和启动器版本。验证一次真实游戏更新、一次补丁更新和一次同签名启动器升级，保持游戏资源与登录状态。

只声明支持实际通过验证的设备组合；游戏登录、后台恢复、16 KB 页设备和更多厂商系统分别记录测试结果。
